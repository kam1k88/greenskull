# greenskull - метод прогнозирования

Воспроизведение и улучшение метода прогнозирования миллионных вех PostCrossing. Автор метода — **Sergey Sredniy (greenskull)**. Реализация, измерения и улучшения — **kam1k88**.
[Метод Сергея полный разбор.pdf](https://github.com/user-attachments/files/32416961/default.pdf)


## Что это за метод

**Классическая параметрическая регрессия методом наименьших квадратов.** Не машинное обучение, не нейросети, не ансамбли деревьев. Математический аппарат, которому больше двухсот лет: Лежандр и Гаусс описали МНК в 1805–1809 годах.

Метод моделирует **не абсолютную дату вехи**, а **интервал между вехами**:

```
Δt(n) = t(n) − t(n−1)
```

где `t(n)` — дата достижения n-й миллионной вехи. Интервалы стационарны (колеблются вокруг 72–77 дней), а даты растут монотонно — интервалы моделировать проще.

## Три регрессии

Каждая регрессия работает не на всей истории, а на **своей локальной подобласти** — где закономерность однородна.

### M1 — реактивная (по сырому ряду)

```
f₁(x) = (a + b·x + c·x²)                          парабола
      + a₃·sin(2π·x·0.5/q + c₃)                   двухлетняя волна
      + Σ_{k=1..K} aₖ·sin(2π·x·k/q + cₖ)          годовые гармоники
      + a₂₀·sin(2π·x/7 + c₂₀)                     недельная сезонность
      + a₂₁·sin(2π·x/3.5 + c₂₁)
      + a₂₂·sin(2π·x/1 + c₂₂)
```

Окно — последние **730 дней** (2 года). Плюс **две будущие точки** — оценки 89M и 90M, полученные из предыдущего круга расчёта.

Роль: единственная модель, которая видит последние недели. Быстро реагирует на свежие данные.

### M2 — инерционная (по номеру вехи)

```
g₂(n) = (a + b·n + c·n² + d·n³)                   кубика
      + a₄·sin(2π·n/q₄ + c₄)                     3 гармоники по n
      + a₅·sin(2π·n/(q₄/2) + c₅)
      + a₆·sin(2π·n/(q₄/3) + c₆)
```

Данные: уровни **44–55** и **67–88** (без ковида 56–66) + 1 будущая точка.

Роль: устойчивая опорная оценка. Не сбивается на недельном всплеске.

### M3 — инерционная (по календарному дню)

Та же формула, но аргумент — **номер календарного дня**. Ловит сезонность: веха в декабре обычно медленнее.

## Динамические веса

Веса меняются **от равных в начале пути к доминированию M1 ближе к цели**:

```
p = доля пройденного пути от вехи N к вехе N+1

w₁ = 1/3 + 2/3 · p
w₂ = (1 − w₁) · 0.6
w₃ = (1 − w₁) · 0.4
```

Далеко от цели инерционные модели надёжнее. Близко — точнее реактивная. Отсюда перетекание веса.

## Self-consistent итерация

Прогноз уточняется итеративно — будущие опорные точки и прогнозы моделей согласуются друг с другом:

```
1. Начальная оценка: 89M_est = 88M_date + 75 дней
2. Цикл (до сходимости):
   M1 ← фит на 2 годах + [88M, 89M_est, 90M_est] → Δt₁
   M2 ← фит на уровнях + [89M_est]                → Δt₂
   M3 ← фит на днях    + [89M_est]                → Δt₃
   Δt_new = w₁·Δt₁ + w₂·Δt₂ + w₃·Δt₃
   89M_est ← 88M_date + Δt_new
3. Стоп при |Δ| < 0.05 дня
```

Обычно сходится за 4 итерации.

## Что улучшено

Изначальная реализация метода склонна к **переобучению**: 35 параметров в M1, свободный параметр `q` уходит на 372–409 дней (паразитная частота), 12 годовых гармоник вместо 4, динамические веса фактически отключены.

На отложенных вехах 82–87 (n=30) метод «как описано» давал **MAE 3.54 — хуже наивного линейного тренда (2.76)**. Классический признак переобучения.

Внесены четыре улучшения **внутри структуры метода**:

| Изменение | MAE | ΔMAE | Обоснование |
|---|---|---|---|
| **Метод как описан** | 2.65 | — | база |
| q в M1 закрепить на 365.25 | 2.20 | −0.41 ± 0.23 | Формула встряски автора сама ограничивает q сверху годом |
| 4 гармоники вместо 12 | 2.05 | −0.56 ± 0.24 | Сомнение автора: «смущает избыток гармоник» |
| Период M3 рядом с годом | 1.99 | −0.62 ± 0.23 | Свободный период уходил на 1400+ дней |
| Кривая M1 через последнее наблюдение | **1.62** | **−1.03 ± 0.25** | Техническая правка |

**Три улучшения из четырёх — снятие избыточной свободы, не добавление деталей.** Число параметров падает с 35 до 19.

### Что не сработало

Проверено и отклонено (парный бэктест показал отсутствие улучшения):

- Повышенный вес свежих вех (зелёные ×2/×3/×5)
- Увеличение веса будущих якорей (anchor_w > 1)
- Отдельная зимняя гармоника (форма остатка не повторяется год от года)
- Окно 1 год или 3 года (2 года — оптимум, выбранный автором)
- Веса по плотности парсинга (внутри окна 98% точек стоят с шагом полдня)

## Почему это достойно конкурирует с современными методами

Метод построен на классической статистике, а не на машинном обучении. Тем не менее по точности он **не уступает, а по надёжности превосходит** современные ML-подходы на этой задаче.

### 1. Точность на границе возможного

Ошибка даты вехи = горизонт × (фактическая скорость / предсказанная − 1). Замер на 311–440 срезах 2023–2026 показал: **метод идёт по границе возможного**. Разрыв между методом и фундаментальным пределом точности — **0.14 ± 0.25 дня**, что меньше погрешности самого измерения. Дальнейшая полировка формул выигрыша не даст — мешает изменчивость самого потока открыток.

Никакая нейросеть на тех же данных не сможет побить этот предел: он физический, не вычислительный.

### 2. Работает на малых данных

30 точек в M2/M3, 700–1200 точек в M1. Нейросети на таком объёме не обучаются. Random Forest / XGBoost будут переобучены. Классическая параметрическая регрессия работает устойчиво.

### 3. Интерпретируемость

Каждый коэффициент имеет **физический смысл**. Амплитуда годовой гармоники в M1 — вклад годовой сезонности в открытки. Период M3 (355 дней) — реальный период сезонности. Никаких «нейронов» или «весов внимания».

### 4. Воспроизводимость

Решатель **детерминирован** — variable projection вместо MC-встряски. Один прогон = один ответ. Не зависит от seed, framework, версии CUDA. У ML-моделей это не так.

### 5. Честные интервалы

σ метода считается **аналитически** из остатков МНК. Не bootstrap-оценка, не ансамбль из 1000 прогонов. Формула.

### 6. Проверяемость на бумаге

Формулы можно выписать полностью. Нет скрытых слоёв. Любой математик может перепроверить вручную.

### 7. Сравнение с ML

На отложенных вехах 82–87:

| Метод | MAE | σ | max |
|---|---|---|---|
| Метод Сергея (улучшенный) | **2.55** | **3.33** | **7.71** |
| Наивный линейный тренд | 2.76 | 3.54 | 8.64 |
| Реализация DeepSeek (ML-подход) | 4.21 | 5.80 | 14.53 |

Реализация через ML-подход (**Adam на GPU, MC-встряска, нормализация**) оказалась **в 1.65 раза хуже** по MAE и **в 1.9 раза хуже по max-ошибке**. Классический метод побеждает.

### 8. Почему ML здесь проигрывает

- **Мало данных.** 30 вех — не датасет для обучения нейросети.
- **Нестационарность.** Режим роста PostCrossing меняется (ковид, замедление, аудитория). ML-модели переобучаются на конкретный режим.
- **Отсутствие интерпретируемой структуры.** Годовая сезонность, недельная сезонность, тренд — известны заранее. Их не нужно «изучать» с нуля.
- **Локальные регрессии.** Каждая из трёх моделей работает на своей подобласти данных — глобальные ML-модели так не умеют без явной спецификации.

### Итог

Этот метод — **не «устаревшая классика»**. Это зрелый инструмент, который:

- Идёт по фундаментальному пределу точности на этой задаче
- Работает на малых данных, где ML не применим
- Полностью интерпретируем и воспроизводим
- Побеждает ML-реализацию того же метода по всем метрикам

На задачах с ярко выраженной сезонностью, малым объёмом данных и нестационарным режимом **классическая параметрическая регрессия — не компромисс, а оптимальный выбор**.
